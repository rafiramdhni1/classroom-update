Karakteristik & Pola Desain Backend

Backend Sistem Informasi Akademik SMK TKJ dibangun dengan pendekatan modular Separation of Concerns (SoC), memastikan setiap lapisan (routing, validasi, logika bisnis, dan interaksi basis data) beroperasi secara independen dan terisolasi.

01

Stateless RESTful

Setiap panggilan API bersifat mandiri menggunakan token JWT di header Authorization. Server tidak membebani RAM dengan sesi memori, memungkinkan respons cepat dan keandalan tinggi.

02

Decoupled Worker

Bot Telegram berjalan di proses mandiri (bot-poll.js). Jika koneksi ke server Telegram mengalami timeout, server web Express tetap melayani portal akademik siswa tanpa gangguan.

03

Compound Caching

Data tugas Google Classroom disimpan secara lokal di koleksi CourseworkCache dengan masa kedaluwarsa 5 menit, melindungi server dari blokir rate limit Google API.

Pipeline Middleware & Alur Request (server.js)

Urutan eksekusi middleware pada setiap paket HTTP yang diterima server:

1

app.set('trust proxy', 1)

Memastikan Express membaca IP asli siswa/guru saat berada di balik Nginx Reverse Proxy dan Cloudflare.

2

compression()

Kompresi Gzip otomatis untuk seluruh payload JSON. Mempercepat muat halaman dan memotong penggunaan kuota data hingga 80%.

3

cors({ origin: [FRONTEND_URL, ...], credentials: true })

Pengamanan Cross-Origin Resource Sharing. Menolak request ilegal dari domain asing yang tidak terdaftar.

4

Multi-Tier Rate Limiting (express-rate-limit)

• Global: 200 req / 15 menit
• Login (/api/auth/login): 100 req / 15 menit (mencegah brute force)
• Lupa Password (/api/auth/forgot-password): 5 req / 15 menit (mencegah spam OTP Telegram)

5

Performance Logger (Winston & Monitoring)

Mencatat durasi request dalam milidetik (ms). Jika respon menghasilkan status 500+, otomatis dicatat ke koleksi database error.

Sistem Keamanan, Autentikasi, & RBAC (Role-Based Access Control)

Mekanisme Otorisasi Token

Format Token: Bearer Token JWT dengan payload ID pengguna.

Masa Berlaku: 7 hari (expiresIn: '7d').

Ekstraksi Efisien: Menggunakan query User.findById(id).select('-password').lean() untuk memotong alokasi memori berlebih dan mencegah kebocoran hash password.

Hierarki Hak Akses (RBAC)

[adminOnly]

CRUD siswa, generate kode aktivasi telegram, manajemen akun guru, import data, backup, dan monitoring server.

[staffOnly]

Terbuka untuk guru dan admin: Input nilai manual (spreadsheet), sync nilai Classroom, dan export rekap Excel.

[auth]

Terbuka untuk semua akun terotentikasi: Dashboard siswa, pengecekan peringkat, dan detail tugas.

Enkripsi & Validasi Skema (Zod)

1. Password Hashing (bcryptjs)

Password diamankan dengan algoritma satu arah bcrypt (10 rounds salt). Password asli tidak pernah tersimpan di database.

2. Validasi Skema Input (Zod)

Sebelum data diproses controller, Zod memeriksa tipe data, panjang string, dan pola karakter:

  • loginSchema: Validasi NIS/NISN & password.
  • forgotPasswordSchema: Mencegah manipulasi NIS.
  • verifyOtpSchema: Validasi kode OTP 6 digit.

Koleksi Database MongoDB (Mongoose Schema)

Struktur 8 model dokumen di dalam database smk_akademik:

1. User

Akun Autentikasi

Menyimpan NISN, hash bcrypt, role (admin/guru/student), dan token OAuth Google.

2. Student

Data Induk Siswa

NIS, nama lengkap, kelas, rombel, angkatan, dan mapping classroomId.

3. Grade

Nilai Manual Guru

Nilai UTS, UAS, Praktik untuk 5 mata pelajaran produktif (ASJ, AIJ, TJBL, PKDK, TJKT).

4. CourseworkCache

Cache Tugas Classroom

ID tugas, judul, batas waktu, dan array submissions status pengerjaan siswa.

5. ChatId

Relasi Bot Telegram

Menghubungkan NIS siswa dengan Chat ID Telegram untuk notifikasi pribadi.

6. ActivationCode

Token Aktivasi Bot

Kode heksadesimal acak untuk verifikasi pendaftaran Telegram siswa.

7. PushSubscription

Web Push Browser

Menyimpan endpoint browser & public keys VAPID untuk notifikasi HP.

8. AdminMessage

Pesan Pengumuman

Pesan prioritas dari sekolah dengan filter target kelas dan tanggal kedaluwarsa.

Rekayasa Integrasi Google Classroom & Telegram Bot

Google Classroom Engine (classroom.js)

OAuth2 API

Mengatasi batasan kuota Google API dengan rekayasa khusus:

  • • Concurrency Control: Request paralel dibatasi 4 kelas (COURSE_CONCURRENCY: 4) dan 6 tugas (WORK_CONCURRENCY: 6).
  • • Exponential Backoff: Jika menerima HTTP status 429 (Rate Limit), sistem otomatis melakukan jeda bertahap dan mencoba ulang hingga 3 kali.
  • • Selective Field Masking: Hanya menarik field id, title, dueDate, submissions, memangkas beban payload hingga 60%.

Telegram Bot Daemon (bot-poll.js)

Long Polling

Daemon independen yang mendengarkan perintah siswa secara interaktif:

  • • /start & /help: Menampilkan panduan dan opsi menu.
  • • /aktivasi <kode>: Memvalidasi token aktivasi dan menautkan Chat ID siswa ke database.
  • • /nilai: Menampilkan kartu nilai real-time dan daftar tagihan tugas langsung di obrolan Telegram.
